# Work log — 2026-10-09

Bringing the Zalman ALPHA2 DS LCD back after the Bazzite 44 reinstall, without
patching system packages. All times are local (Europe/Istanbul).

## Starting point

- CoolerControl 5.0.1 and liquidctl 1.16.0 were installed as stock rpm layers
  (`ujust install-coolercontrol`), and `coolercontrold` was running.
- The LCD was present at kernel level (`0483:5740` → `cdc_acm` → `/dev/ttyACM0`), but
  CoolerControl reported `liquidctl devices found: []`.
- Cause: the previous setup relied on a patched coolercontrold and a liquidctl
  Zalman driver installed into `/usr/local` with `sudo pip`. Both were lost in the
  reinstall, and neither upstream project supports the panel.

## Decision

Instead of re-patching coolercontrold and liquidctl, write a **CoolerControl
device-service plugin**. CoolerControl 5 supports these plugins over gRPC (`cc-plugins`),
and the proto defines an LCD channel. The plugin wraps the existing driver
(`zalman_lcd.LcdClient`, bl3xand's protocol work, MIT). Constraints set by the user:
reversible, no damage to the system, nothing written to `/usr`.

Full plan: [PLAN-zalman-lcd-plugin.md](PLAN-zalman-lcd-plugin.md).
